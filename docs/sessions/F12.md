## Design notes

- Explore lands on Strategies because the reference does; `tab=` values
  stay stable so F05 links and tests keep working (`tab=instruments`).
- Nothing in a row is computed by the app except labels: the rank, the
  return, the drawdown, the history, the completeness and the reasons are
  the API's ranking entry, so the explorer can never show a rank the
  leaderboard does not. Follower counts are counts; sorting by followers
  is labelled as a popularity order and is not a rank.
- Universe is derived from issuers (PreStocks issues pre-IPO exposure,
  xStocks listed stocks) and says so in the docs; it is a label for the
  mix, not a claim about a company.
- The public queries carry no reader state by construction (keys hold
  filters only; the API has no field for it); Following is a private
  query composed at render time, never written into public entries and
  never requested while signed out.
- Accepting a version is one explicit call with the version id the person
  read, after the diff; the panel says a rebalance is a separate plan.
  A hidden or unregistered proposed version is shown as unacceptable
  rather than pinned blindly.
- Discovery reads are not retried when the API answered (anything below
  500, or a contract mismatch); a rate limit is shown as one.

## Verification

Every claim above was exercised against the local API and the fixture
ledger, never against a recorded response:

- The Explore Strategies tab, the rankings page, the creator page, the
  provenance and ranking line on a public strategy page and the model
  performance panel on a public version page render from the four public
  reads the proxy now forwards (`GET /v1/strategies`, `GET /v1/creators/
  {publisherWallet}`, `GET /v1/rankings/model`, plus the F08 and F11 public
  reads) and from nothing else; the jsdom tests assert that a signed-out
  visitor triggers no `/v1/me/follows` read and sees no Following state.
- Ranks, returns and drawdowns appear only when the ranking entry is
  eligible; a young or incomplete recipe shows the methodology's reason in
  its own words and no percentage (jsdom and the browser journey, where the
  freshly registered recipe has 0 of the 30 required days).
- Following changes the private follows list only; the browser journey
  confirms that the follower's instance holds no position and that nothing
  is bought or sold when the proposal is accepted (the pin moves to version
  2 and the target table re-reads from that version).
- The proposal diff is computed from the two public version documents with
  the F08 diff and matches the backend's one-sided turnover; acceptance
  posts exactly the proposed version id, and a proposed version that is no
  longer public (hidden or a 404) leaves the button disabled with the
  reason.
- Failures stay failures: a rate limit, contract drift and an expired
  cursor page render as errors with a retry or a reset, never as an empty
  list or demo rows.
- `pnpm verify` ran green after the last edit (87 files / 640 tests), and
  the Playwright journey ran on a fresh production build with internal
  routes enabled (2 passed).

Not verified in this session: no live network, no mainnet, no real
follower population beyond the fixture users; the follower count in the
browser journey is 1 because one fixture user followed.

## Unresolved risks and dependencies

- The instance a follower pins is created in the journey with the same
  `POST /v1/me/instances` call the review start makes (F11), not through
  a full funded review; the review path itself is covered by the F09 to
  F11 journeys.
- Moderation restrictions are covered by the B14 API test and by jsdom
  (a hidden proposed version, a not-found strategy); the browser journey
  has no operator credential with `ops:discovery:write`.
- Deprecated versions stay listed with their marker (the creator's own
  statement); a product decision on de-emphasising them is open.
- Rankings are read live from the API (bounded population, 60/min); a
  persisted snapshot is a backend follow-up (with OD-23).
- The single-row top-bar layout of the reference remains for F19.
