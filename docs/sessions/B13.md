## Design notes

- A point sits at every external flow, so each flow closes its own
  subperiod and the flow-timing convention is exact rather than assumed;
  the daily grid only adds resolution for drawdown and completeness.
- The instance series treats a purchase as a contribution of its cost and
  a sale as a withdrawal of its proceeds, valued at par of the cost asset,
  so execution cost against the reference price is visible as return and
  the wallet's cash never enters the instance.
- The model series buys whole base units at the first priced point after
  the freeze and never rebalances; rebalancing, fees and slippage are
  stated as absent rather than approximated. Rankings compare one period
  and one methodology version; ties break by drawdown then version id.
- Everything is computed on read from the recorded observations, the
  journal and the lots; a snapshot job and the live price sources are
  OD-23. Nothing invents a price, a multiplier or a return.

## Verification

The first startup-check run reported the wallet series as
`incomplete_points`: in that journey the fills settle before the wallet is
ever reconciled, so the journal carries fees and spent stablecoin before
the inflow entries that reconciliation later dates at its observation
time, and the series started at the first fill with negative balances
(`negative_quantity`). That is a truthful reading of the journal but not a
useful series, so the wallet series now starts at the wallet's first
reconciliation checkpoint, the first time the platform observed it on
chain, with everything journaled before it as the opening position
(`earliestCheckpointAt`; a wallet never reconciled still starts at its
first entry and shows the negative quantities). The API test asserts the
start equals the first checkpoint's observation time and the second
journey run reports the window `available`. `pnpm lint` also caught the
boundary rules file reformatted by a script (fixed with the formatter).
The full gate then ran green: lint, typecheck, 82 test files with 582
tests (15 analytics vectors and rules, 1 analytics API journey among
them), boundaries, OpenAPI, generated client, migrations, tokens and the
web build.

## Provider verification status

No provider is involved: every observation comes from the fixture feeds
(recorded at ingestion) or from operator entries made by the tests and
the startup check, and every series is computed against the fixture chain.
No live reference price, SOL price or stablecoin observation exists
(OD-23); the capability `analytics.performance` is FIXTURE_VERIFIED. No
funds were spent, nothing was published, no mandate was created and no
message was sent.

## Unresolved risks and dependencies

- Live price sources (issuer marks, secondary-market prices, underlying
  equity prices, SOL and the stablecoin) are not integrated; a production
  series is incomplete until they are recorded (OD-23). Whether a token's
  own market or the underlying's price is authoritative per issuer is part
  of that decision; today the underlying price values a token only as a
  stated assumption.
- Series and rankings are computed on read and bounded (20,000
  observations, 5,000 journal entries, 500 rankable versions); a persisted
  snapshot job is needed before the public population grows.
- The instance series values purchases and sales at par of the cost
  asset; a stablecoin depeg at a fill time is not yet reflected in the flow
  value (the flow is a par amount of the cost asset by construction).
- Fees are attributed to an instance only when the journal attributes the
  fee entry to it; wallet-level fees are complete.
- The 30-day ranking threshold is a product rule; the methodology
  version must change with any rule change so cohorts never mix.
