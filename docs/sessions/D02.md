# D02: Accurate source links and a public content inventory

Session D02 of the documentation plan (D02 to D09), run after P01 on
2026-09-25 on branch `claude/affectionate-gauss-2ml7ll`.

## Working behaviour

- **Publication manifest.** `apps/docs/content-manifest.json` lists every
  page markov.pet/docs publishes and nothing else: the 9 hand-written site
  pages (`sitePages`), the 77 repository documents synced into the site
  (`pages`, each with its public id, `audience` of `user`, `developer`,
  `operator` or `reviewer`, and `kind` `curated`), and the two generated
  references (`generated`: the API reference from `docs/markov/openapi.json`
  by `generate-api-reference.mjs`, the CLI reference from
  `apps/cli/src/program.ts` by `generate-cli-reference.mjs`). The sync no
  longer publishes whatever lies in `docs/markov`, `docs/frontend` and
  `docs/sessions`: a new file there stays off the site until the manifest
  lists it (the sync reports such files as not published). A listed source
  that is missing, a duplicate id or source, an unknown audience, a path
  that leaves the repository, or a page under `apps/docs/docs` that the
  manifest does not list fails the build with every problem named
  (`apps/docs/scripts/content-manifest.mjs`). The published set is the one
  D01 published; nothing was added or removed.
- **Where a build comes from.** `apps/docs/scripts/source-metadata.mjs`
  resolves the source once per build and writes only the resolved fields
  to `apps/docs/generated/source.json` (gitignored): the commit from
  `MARKOV_DOCS_SOURCE_COMMIT`, `VERCEL_GIT_COMMIT_SHA` or `GITHUB_SHA`
  (validated as a full hash, and refused when it differs from the
  checked-out commit), otherwise from a clean checkout; a checkout with
  uncommitted changes or no metadata at all is recorded as
  `local-uncommitted` or `unknown`, never guessed. The edit branch is the
  manifest's `maintainedBranch` (this branch until the owner merges into
  `main`, which holds only the initial commit), or
  `MARKOV_DOCS_EDIT_BRANCH` when it is a valid branch name; anything that
  could carry a query, fragment, scheme or traversal is refused.
- **Links.** The hard-coded `main` is gone from `docusaurus.config.ts`,
  `sync-content.mjs` and both generators. Source evidence (the file a page
  was published from, repository files a document links, the generators
  and their inputs) links to `blob/<commit>/…`; edit links go to
  `edit/<maintained branch>/…`; branch and path segments are encoded one
  by one, so `claude/affectionate-gauss-2ml7ll` stays a readable path.
  Every synced page opens with a source note naming the file and the
  commit; the footer names the commit the site was built from, or says
  that this is a local build with no verified revision. Generated pages
  have no edit link; their note links the input and the generator at the
  same revision. Embedded repository images are copied next to the page
  and bundled (`_assets/`); nothing hot-links a branch. Link rewriting is
  a pure module (`apps/docs/scripts/rewrite-links.mjs`) and refuses a
  relative path that leaves the repository.
- **No secrets in the bundle.** The build copies nothing from the
  environment but the resolved commit and branch; CI now scans the built
  site (`apps/docs/build`, including the search index) with the pinned
  gitleaks and keeps the report and the resolved `docs-source.json` with
  the build evidence.
- Documentation: `docs/markov/operations.md` (documentation site: the
  manifest, source resolution, the two variables) and the site's
  contributing page (publishing is explicit; leaving a file out of the
  manifest is not confidentiality).

## Unresolved risks and dependencies

- The maintained branch is a working branch until the owner merges into
  `main`; the manifest must change in the commit after the merge, or edit
  links keep pointing at the working branch.
- A pull-request build pins GitHub's temporary merge commit; those links
  stop resolving once the pull request is closed. Deployed builds pin the
  pushed commit.
- The Vercel project does not deploy on push (the Vercel GitHub App is not
  installed); the deployed site keeps the D01 build, with `main` edit
  links, until it is redeployed.
- The published set is unchanged from D01; which engineering documents
  belong on a public user-facing site is D03's information architecture.
