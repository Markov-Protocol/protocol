# Session F04 — Wallet, eligibility and funding readiness

Session: F04 — verified wallet and trading readiness flows
Date: 2026-09-24 · Branch: `claude/affectionate-gauss-2ml7ll`

## Behavior delivered

- Backend (additive): `GET /v1/me/wallets/{walletId}/funding` reads the
  configured RPC endpoint (`getBalance`, `getTokenAccountsByOwner`,
  `getMinimumBalanceForRentExemption`, all added to the bounded client)
  and reports SOL and stablecoin balances at a stated slot, the rent-exempt
  minimum for a token account, the base fee allowance (5,000 lamports per
  signature, two signatures) and a readiness verdict; 503 when the endpoint
  cannot be read. `FUNDING_STABLECOIN_MINT` configures the stablecoin;
  USDC is the default on mainnet-beta only. The fixture RPC answers funding
  reads from a test control endpoint; the e2e API script publishes the
  fixture rules and terms. OpenAPI and `@markov/api-client` regenerated.
- App server: `/api/markov/*`, an allowlisted proxy that attaches the
  HttpOnly session as the bearer, forwards the client address, enforces
  same-origin JSON mutations with a size limit, drops upstream headers and
  never caches.
- Wallets (`apps/web/src/features/wallets`): Wallet Standard discovery with
  capability discovery (`solana:signMessage`, `solana:signTransaction` and
  versions, sign-and-send marked unsupported, chains); explicit selection
  and account choice; connection states (none, connecting, choose-account,
  connected, declined) separate from signed-in, verified and eligible;
  network check against the platform cluster; ownership verification that
  shows the exact B02 challenge, requires a byte-identical `signedMessage`
  and a 64-byte signature, and discards signatures obtained under another
  session epoch or after the wallet's accounts changed; error mapping for
  replay, already-linked (recovery guidance, no automatic transfer),
  stale sign-in, rate limit, declined and altered signatures; unlink with
  confirmation behind step-up; disconnect distinct from sign out; a wallet
  chip in the top bar; the chosen wallet's name is the only browser-side
  fact, used to resume it silently after a reload and cleared on
  disconnect.
- Funding (`features/funding`): receive panel with the person's own
  address (full text, copy, QR drawn from the encoder matrix), cluster and
  stablecoin mint, observed balances, fee requirement and basis; unknown
  shown as unknown; no pooled address, bridge, onramp or deposit credit.
- Eligibility (`features/eligibility`): outcome and standing, the API's
  summary, declaration form (self-declared, attested), terms acknowledged
  by content hash, await-review and verify-wallet steps, a no-evasion
  notice on denial.
- Settings index, `/settings/wallets`, `/settings/eligibility`, a private
  page gate, and the home checklist driven by live readiness facts.

## Open dependencies and release impact

- Real wallet coverage (Phantom, Solflare, hardware, mobile handoff) needs a
  browser with those extensions; the fixture wallet proves the protocol
  path only.
- The embedded wallet stays an unavailable option until a hosted provider is
  chosen and integrated (OD-05).
- Live balance reads need a reachable cluster endpoint; only the fixture RPC
  was exercised. Devnet USDC was not verified from a primary source, so it
  is not defaulted (`FUNDING_STABLECOIN_MINT`).
- Fee requirements are an allowance from the documented base fee and the
  live rent-exempt minimum; the exact fee payer and priority fee arrive with
  a plan (B10).
- Funding readiness reads balances at request time; there is no
  subscription or history.
