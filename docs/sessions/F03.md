## Behavior delivered

- `packages/api-client` (`@markov/api-client`): path and body types
  generated from the frozen OpenAPI document (`pnpm api-client:generate`,
  drift-checked by `pnpm api-client:check` in `verify` and CI), a typed
  client with bearer and forwarded-address middleware and a per-request
  timeout, runtime validation with the shared zod contracts, typed error
  envelopes (`MarkovApiError`, `MarkovApiUnreachableError`,
  `MarkovContractMismatchError`) and the route-to-contract matrix proven by
  a compatibility test.
- Backend (additive, within B02's architecture): `identityProvider` on
  `GET /v1/platform` and `session { sessionId, expiresAt }` on `GET /v1/me`;
  OpenAPI regenerated; API tests updated.
- App server (`apps/web/src/server`): server-only `MARKOV_API_ORIGIN`;
  host-only HttpOnly session cookie (`__Host-markov_session`, Secure,
  SameSite=Lax, Path=/; plain name only for local http); same-origin guard
  for mutations; validated local return paths; `GET /api/auth/session`,
  `POST /api/auth/sign-in`, `POST /api/auth/sign-out` route handlers built
  on framework-neutral functions; session resolution on every request with
  honest *unavailable* state when the API cannot be reached; account change
  revokes the previous session; the browser's address is forwarded so the
  API's per-client limits apply per person.
- App client (`apps/web/src/features/auth`): `SessionProvider` with
  explicit states (signed-out, signed-in, expired with recovery,
  unavailable) and a session epoch; `useSessionFetch` aborts in-flight
  requests on principal change and rejects late responses; one TanStack
  Query client per principal and epoch, disposed on sign-out, expiry and
  switch; expiry timer, back/forward-cache and hidden-tab re-verification,
  credential-free cross-tab notification; the one sign-in screen offering
  exactly the backend's identity path (development issuer marked
  nonproduction; hosted provider honestly BLOCKED); `/auth/callback` with
  cancelled, failed, unsupported and empty outcomes; top-bar account menu
  (Settings, Switch account, Sign out) and real connection status; signed-in
  home with a dismissible next-step checklist whose items state their
  delivering sessions.
- Evidence: Playwright journeys against the real API on both device
  profiles, screenshots in `docs/frontend/evidence/F03/`.

## Open dependencies and release impact

- OD-05 blocks any real sign-in: the hosted provider's browser adapter,
  its callback configuration and the exact issuer/audience/key facts are
  unverified. Until then the app can only sign in against a backend that
  runs the test issuer, which production configuration refuses.
- The app forwards the first `X-Forwarded-For` hop; the deployment's proxy
  must overwrite that header, and the API must trust only the app server.
- Safari's treatment of Secure cookies on `http://localhost` is untested;
  local http uses the plain cookie name by design.
- Session renewal is deliberately absent; long sessions rely on
  `AUTH_SESSION_TTL_SECONDS`.
- Step-up (fresh sign-in for security changes) is exposed in the session
  state but no screen uses it until F04.
