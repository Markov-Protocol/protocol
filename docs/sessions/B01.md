## Starting state

`Markov-Protocol/protocol` at `09c7ce6` contained `README.md` (one line) and
an Apache-2.0 `LICENSE`. No code, no CI, no schema. Shortest safe path to a
runnable backend: a fresh pnpm monorepo with strict configuration, a
migration-bound platform identity and health/readiness on top of PostgreSQL
and Temporal, before any financial feature.

Build environment: Node 22.22.2, pnpm 10.33.0, PostgreSQL 16.13 (local
server), Temporal CLI 1.9.1 dev server (installed by checksum), gitleaks
8.30.1. Docker was not available. Egress policy blocked the public Solana RPC
endpoints and every vendor documentation host (see
`docs/markov/source-register.md`, SR-EGRESS-01).

## Limitations and unresolved risks

- Genesis hash constants were live-verified for all three public clusters
  through a read-only QuickNode RPC session (SR-SOL-01), but the
  `@markov/solana-rpc` client itself never reached a live endpoint from this
  environment, so `solana.rpc.read` remains FIXTURE_VERIFIED until
  `markov solana probe` runs with real endpoints.
- `docker-compose.yml` was written from the upstream Temporal compose layout
  and not executed (OD-16). The verified local path is the Temporal CLI dev
  server plus a local PostgreSQL.
- The API has no authentication yet and exposes only platform metadata; it
  must not be deployed publicly before B02.
- OpenTelemetry tracing and metrics are not wired (OD-03); logs are
  structured and redacted.
- The CI workflow was authored but has not run on GitHub yet; it will run on
  the first push/pull request of this branch. Any failure there is B02's
  first task.
- Local git hooks can be bypassed; CI's range check is the enforcement point.
- `pnpm audit` reports one moderate advisory (GHSA-67mh-4wv8-2f99, esbuild
  <= 0.24.2 reachable only through drizzle-kit's deprecated
  `@esbuild-kit` loader, a development-time tool that never runs a dev
  server here). CI blocks on high and above; track an upgrade of drizzle-kit
  that drops the loader.
