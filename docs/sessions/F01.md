## Behavior delivered

- `apps/web`: Next.js 16 App Router workspace with strict TypeScript,
  Tailwind v4 over CSS-variable tokens, self-hosted Inter, a validated
  web environment (`MARKOV_ENV`, `MARKOV_WEB_INTERNAL_ROUTES`,
  `MARKOV_WEB_FIXTURES`, `NEXT_PUBLIC_APP_ORIGIN`) enforced at build and
  server start, baseline security headers, a minimal home page and
  not-found page, and the internal `/dev/components` reference route
  (disabled in production).
- `packages/ui`: tokens as the single source (`tokens.ts` → generated
  `tokens.css` with a drift check), base styles, `Button` (with
  `disabledReason`), `Field`, `TextInput`, `TextArea`, `SearchInput`,
  `SelectInput`, `AmountInput`, `PercentInput`, `ValidationSummary`,
  `StatusBadge`, `Notice`, `EmptyState`, `ErrorBlock`, `Skeleton`,
  `Dialog`, `Menu`, `Tabs`, `Table`, `VisuallyHidden`, and a
  token-aware `cn()`.
- `packages/formatters`: exact raw-amount, decimal-string, basis-point,
  typed-price, time and address formatting and parsing with no floats.
- `@markov/contracts`: typed price kinds, decimal/raw-amount/basis-point
  schemas shared with the backend.
- Tooling: vitest projects (node + jsdom), boundary rules for the
  frontend/backend split (`appDeny`), CI steps for token drift, web build,
  guard refusal and Playwright evidence.
