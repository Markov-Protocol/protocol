  every push, on pull requests and on manual dispatch (manual dispatch works
  once the workflow is on the default branch). Before P01 it ran only on
  pushes to `main` and pull requests; `main` holds only the initial commit

- **Retained, redacted evidence instead of an echo.** Each job writes its
  logs and reports to `ci-evidence/<artifact>/`, runs the evidence gate and
  uploads: `checks-reports` (commit policy, lint, typecheck, release status,
  boundaries, tokens, OpenAPI, client and migration drift, Vitest JUnit and

- **Evidence gate** (`scripts/ci/evidence-gate.sh`): redaction of
  credential-shaped values in text files, inside ZIP archives (Playwright
  traces, nested archives) and inside the archive a Playwright HTML report
  embeds (`tooling/release/redact.mjs`, a small ZIP reader and writer on
  Node's zlib), including trace-recorded `{"name":"cookie","value":…}`
  headers, values behind terminal colour codes and the Ed25519 PKCS#8 key
  shape, with `[redacted]` placeholders that keep JUnit XML well formed;
  uninspectable archives are deleted; a verify pass; then gitleaks with the
  default rules plus the Markov credential and key formats
  (`tooling/release/evidence-gitleaks.toml`) over the directory and over the
  extracted report archives. A finding blocks the upload with exit 1 and
  prints what tripped it, redacted; a missing or failing scanner exits 2.

  wallet used to import its Ed25519 private key inside the page, so a
  failed wallet test's trace would have carried it. It now signs through a
  function exposed on the browser context; the page holds only the public
  key.

## Unresolved risks and dependencies

- **Owner decisions on capability states.** `execution.jupiter.quote` and
  `execution.jupiter.build` are FIXTURE_VERIFIED against synthetic
  Markov-contract quotes, never a recorded Jupiter response;
  `receipts.signing` and `analytics.performance` are FIXTURE_VERIFIED with a
  local key and derived vectors; `maintenance.scheduler` is IMPLEMENTED on
  evidence comparable to `accounting.journal` (FIXTURE_VERIFIED). The
  definition now covers these uses; whether some should read BLOCKED is the
  owner's call and would change the seeds, the reviewed table and the
  manifest together.
- **Code gaps found by the audit** (not fixed here; they belong to the
  sessions named): the policy gate `VENUE_DISABLED` reads only the
  readiness row and treats IMPLEMENTED or FIXTURE_VERIFIED as enabled (P08,
  P09); no operator path updates capability rows, so a database seeded
  earlier keeps older rows (P18); policy exposure is still caller-declared,
  the `ledger` source has no producer (P09, P12); outbox rows other than
  `execution.pending` are written after their state change, not in the same
  transaction (P09); `markov agent call` exits 2 for invalid JSON input where
  every other usage error exits 64.
- **Evidence limits.** Redaction recognises known credential formats;
  anything else relies on tests not printing secrets (e2e assertions on
  credentials are boolean, so a failure does not echo the value).
  Screenshots and other binaries are inspected by neither redaction nor
  gitleaks (its default allowlist skips images); they show pages of the
  run's throwaway test accounts. Browser traces keep test data of the run's
  throwaway database. Artifacts expire after their
  retention; a release copies the bundle into its record (RC-14).
- **Manual dispatch** needs the workflow on the default branch; until then
  the push trigger runs CI.
- The owner authorised a devnet deployment of the registry program on
  2026-09-25 in this conversation; the deployment stays blocked on network
  access and on the P10 prerequisites (reproducible build, upgrade-authority
  process, OD-10).
