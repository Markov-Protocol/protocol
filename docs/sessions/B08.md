## Delivered

- `programs/strategy-registry` (Anchor 0.31.1, `solana-program` 2.3,
  Rust 1.94.1 pinned by `rust-toolchain.toml`, `Cargo.lock` committed): a
  noncustodial program with two instructions. `register_version` creates
  the record at `["version", manifest_hash]` after every rule
  (`check_register_args`: schema 1, non-zero hashes, 1–10 legs, weights
  ≥ 1, no default mint, SPL Token or Token-2022 only, legs strictly
  ascending by mint, checked `u32` total of exactly 10,000 with cash,
  relation and parent consistency) and the account constraints (signer,
  seeds, system program, an optional registered parent record); it stores
  publisher, hashes, legs, cash, lineage, slot and time. `set_status`
  changes only the status byte and its slot and needs the publisher's
  signature (`NotPublisher`). No custody, swaps, fees, delegates,
  authority transfer or operator instruction. `docs/markov/strategy-registry.md`
  is the contract; ADR-0008 records the design and the Anchor pin.
- Program tests under `solana-program-test` (real runtime, native
  processor through a lifetime adapter): registration with clock evidence
  and rent-exempt space; duplicate initialisation by the publisher and by
  a stranger with byte-identical record; unauthorized publishing (no
  signature → `AccountNotSigner`, stranger status change → `NotPublisher`);
  seed and account misuse (other hash's PDA, keypair record, wrong system
  program, unexpected parent, missing parent, non-record parent,

the program's behaviour is proven under `solana-program-test` and the

## Unresolved risks and dependencies

- Anchor is pinned to 0.31.1 because the 1.x line's CPI has no host
  implementation under `solana-program-test` (ADR-0008); upgrading is a
  reviewed follow-up once SBF tooling and a validator are available, with
  the shared vectors as the regression suite.
- No Anchor IDL is committed: generation is blocked by a dependency
  incompatibility under the `idl-build` feature (see the command table);
  the tool crate `programs/idl-build` is ready for an environment with the
  Anchor CLI or a compatible dependency set.
- A validator run with a deployed devnet program, a reproducible build
  hash, an independent review (OD-09) and the upgrade-authority multisig
  and change process (OD-10) are release gates before any publication
  outside local fixtures.
- `moderation` is a database flag without a route; who may set it is open
  (OD-20). Follow/unfollow and discovery listings are F08/B14 work.
- The indexer mirrors at most 5,000 program accounts per pass and reads
  `getProgramAccounts` without pagination; a large registry needs a
  cursor or a slot-based scan.
- The startup check and the API tests share the placeholder program id
  through the fixture ledger; a real deployment sets `REGISTRY_PROGRAM_ID`
  and the fixture control endpoint must never exist outside local/test
  (`scripts/dev/fixture-rpc.mjs` is a development script).
