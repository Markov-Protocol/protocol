# Session B02 — Verified accounts and wallet ownership

Date: 2026-09-24 · Branch: `claude/affectionate-gauss-2ml7ll` · Commit:

## Delivered

- `@markov/auth`: provider-neutral identity-token verifier (jose; issuer,
  audience, expiry, asymmetric algorithm allowlist, remote JWKS rotation),
  nonproduction ES256 test issuer, canonical wallet ownership challenge
  bound to domain, chain genesis, account, nonce and time window, Ed25519
  signature verification with Node's native crypto, peppered opaque
  credentials with non-secret prefixes, principal classes, scopes and
  step-up freshness.
- `@markov/contracts`: base58 codec with vectors; identity contracts
  (principal classes, agent/operator scopes, device capabilities, session,
  wallet, credential, device, operator and audit schemas); new error codes
  `STEP_UP_REQUIRED`, `CHALLENGE_INVALID`, `WALLET_ALREADY_LINKED`.
- `@markov/config`: `IDENTITY_*`, `CREDENTIAL_PEPPER`, `AUTH_*`,
  `WALLET_CHALLENGE_*` with fail-closed invariants (test issuer, development
  pepper and localhost challenge domain refused outside local/test; OIDC
  needs issuer, audience and JWKS; symmetric algorithms refused).
- `@markov/db`: migration `0001_identity` (users, sessions, wallet
  challenges, wallet links with a partial unique index on active links, API
  credentials, device pairings, devices, audit events) and an owner-scoped
  identity store with atomic single-use consumption.
- `apps/api`: auth plugin deriving the principal from the bearer token,
  identity service, routes for sessions, me, wallets, credentials, devices
  and operator views, per-route rate limits, audit records, error mapping.
- `apps/cli`: `auth test-token`, `auth session`, `auth whoami`,
  `auth demo-wallet-link` (nonproduction) and `operators create`.
- Headless journey: `scripts/ci/startup-check.sh` now mints a test token,
  exchanges it, reads `/v1/me`, links a demo wallet and asserts an unknown
  bearer is rejected.
- OpenAPI regenerated; docs: `identity-and-principals.md`, `api.md`,
  `threat-model.md`, `provider-capabilities.md`, `source-register.md`,
  `open-decisions.md`, `operations.md`, README, `.env.example`.

## Limitations and unresolved risks

- No live identity provider was configured or verified; the OIDC path is
  exercised only through the local JWKS variant of the same verifier.
- Cookie sessions, CSRF and browser return paths are the app layer's job
  (F03).
- Rate limits are per client address; production must set
  `API_TRUST_PROXY` correctly.
- Terms/eligibility acknowledgements (B05) and account disabling routes
  (B18) are not part of B02.
